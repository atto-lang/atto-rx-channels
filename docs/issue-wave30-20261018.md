# Observable channel correctness gates — draft 2026-10-18

Issues #8 (lossless one-item Selectable) and #18 (terminal/cancellation/sender linearization).

## Proposed one-item `next` admission (#8)
A one-item adapter may return `ITEM(value)`, `COMPLETED_EMPTY`, `ERROR(e)`, or `CANCELLED`, each exactly once per subscriber. The selected item is transferred exactly once, independent of producer/consumer timing. Cleanup must not consume another item, block forever on an empty channel, or rewrite a terminal token into an otherwise valid user event.

## Linearization points (#18)
- Sender: reserve bounded credit → publish payload/terminal event → commit. Failed publish releases credit exactly once.
- Terminal: completion/error wins once and bars all later user values, even if callbacks race a cancellation.
- Cancel: mark terminal ownership once and unblock outstanding receiver/sender registrations without spurious `COMPLETED_EMPTY`.
- Maintain a CONTROL path that cannot be starved by data traffic.

## Interleaving vectors
1. Completion before first subscriber; subscriber receives empty terminal exactly once.
2. Two producers race `complete` and `error`; only one terminal is observable.
3. Cancel while bounded queue is full; no permit leak, deadlock or duplicate completion.
4. Sender accepted just before terminal commit; either delivered in order or rejected deterministically.
5. Subscriber registered before async producer; no lost wakeup.
6. `take(1)` receives item then immediately cancels; no second source read or leaked subscription.
